## Efficient operation (Claude sessions)

**New session:** start with `docs/claude/state/HANDOFF.md` (generated by
`scripts/claude_handoff.py`; regenerate when stale) and `docs/claude/SESSION_PLAYBOOK.md`
(environment, GitHub-from-session limits, sealing, engine-fork and security-change practice).
The SessionStart hook (`.claude/hooks/session-start.sh`) prints the HANDOFF path and builds the
project venv in cloud sessions. Once the conversation is long, start a new session from
HANDOFF.md instead of compacting a huge transcript.

Tooling only; it changes no policy, gate or evidence rule above.

**Routing defaults (quota).**

- Implementation, mechanical fixes, CI repairs and long background work → `/oc`
  (DeepSeek V4.1 Flash, native max), dispatched with
  `python3 .claude/skills/lab-ops/scripts/oc_dispatch.py post --issue N --lane oc --task FILE`
  from a skeleton in `.claude/skills/lab-ops/oc_tasks/`; watch with `oc_dispatch.py watch` in
  the background. Never hand-write a long dispatch comment.
- Read-only audits and evidence sweeps → `/bunny`.
- Log, CI and diff digests or comparisons → Sonnet `high` subagents (`log-scanner`,
  `ci-triage`, `Explore`).
- Opus main session → only adjudication, final evidence review, merge decisions and
  dispatch.
- Opus subagents → only for an `evidence-reviewer` pass before a qualification push.
- Every agent report ≤40 lines; user status messages ≤8 lines.
- `gh_ops.py brief` is the one-screen lane status; prefer it to any MCP check/comment dump.

- **Skill `lab-ops`** (`.claude/skills/lab-ops/`): one-screen lane brief, one-line PR/CI/thread status, failing-job lines, CI waiting, open-PR queue (`gh_ops.py queue`), re-run of infrastructure-cancelled jobs (`rerun-cancelled`), `/oc` and `/bunny` dispatch + watch (`oc_dispatch.py`), PB-03 packet + AF00–AF11 summary, real-engine row runs. Prefer it to raw MCP check/comment/log dumps; use MCP for writes (replies, resolves, merges, PRs).
- **Skill `piv-validate`**: this repository's real validation commands.
- Other skills route via `.claude/skills/COMMANDER_ROUTING.md`.
- **Subagents** (`.claude/agents/`): every subagent runs on at least Sonnet at `high` effort; judgement stays on the main model.
  - `log-scanner` (Sonnet, high) digests large logs and evidence JSON.
  - `ci-triage` (Sonnet, high) classifies a red check.
  - `evidence-reviewer` (main model, high) reviews a qualification diff adversarially before a push, especially when no external review is available.
  - `log-scanner` and `ci-triage` are read-only reporters inside an authorized Claude campaign. They are not Foundry executors (`docs/foundry-execution/ROUTING_AND_EFFORT.md`) and hold no write, adjudication or merge authority.
  - Evidence adjudication, Rules/CR reasoning and merge decisions are never delegated to a smaller model.
- **Effort.** Claude Opus 5.5 sessions run at `medium` or `high` effort; no Claude subagent runs below Sonnet at `high`. `.claude/settings.json` sets `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` for subagents without their own model; when starting a built-in one (`Explore`, `general-purpose`), pass `model: "sonnet"` or leave it to inherit the main model, never `haiku`. The native-`max` rule in `docs/foundry-execution/ROUTING_AND_EFFORT.md` applies to the OpenCode profiles only.
- **Hook** (`.claude/settings.json`): `ruff --fix` + `ruff format` run on every edited Python file under `src/`, `tests/`, `scripts/`, `.claude/`. Unfixable findings come back in the same turn.
- **Long runs** (Java suites, PB-03, CI waits): start them in the background and keep working. Test narrow while iterating, then run the full suite once before the push.
