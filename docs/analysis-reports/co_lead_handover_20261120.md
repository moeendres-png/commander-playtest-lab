## Rollen und Arbeitsweise
- **Co-Lead** koordiniert, entscheidet Zuschnitt und Reihenfolge, mergt. **Builder** (je 1 Issue = 1 Branch = 1 PR) bauen, **Reviewer** (Frischkontext, nie der Autor) prüfen mit exakter Head-SHA. Briefing-Vorlage für Builder: `builder_rules.md` (diese Ordner) plus Aufgabenblock (Issue, Umfang, Grenzen, was parallel läuft, Bericht ≤15 Zeilen).
- **Reviewer-Auftrag (Vorlage):** Clone `git fetch origin pull/N/head`, `PYTHONPATH=<clone>/src`, Issue samt Kommentaren und vollständigen Diff lesen, Zählregeln/Statistik von Hand nachrechnen, **mindestens 6 Mutationen selbst ausführen und ehrlich zählen**, schmale Tests mit `COMMANDER_LAB_CACHE_CHECK=1`, `ruff`, `node --check`, CI per Check-Runs-API, Fazit PASS / PASS mit Auflagen / BLOCKIERT mit Head-SHA. Reviewer schreibt nichts auf GitHub und mergt nie; der Co-Lead trägt das Verdikt als Review-Kommentar (Klasse A/B nennen, Befehle, SHA) ein.
- **Delta-Review:** nach Fixes prüft derselbe Reviewer nur das Delta auf dem neuen Head. Rein textliche Einzeiler liest der Co-Lead selbst.
- **Merge-Regel:** `quality`, `security`, `infrastructure` auf **genau dem Head**, der gemergt wird. Hat sich `main` seit dem geprüften Head bewegt: `PUT /pulls/N/update-branch`, CI auf dem Merge-Head abwarten, Nachtrag-Kommentar, dann `PUT /pulls/N/merge -f merge_method=squash -f sha=<head>`. Nie „Closes #N“ (immer „Refs“), Issues manuell mit Verweis schließen.
- **MATERIAL-Klassen (E15 Q10, `AGENTS.md` §10, Owner-Entscheid 2026-11-20 „Option 1“):** Klasse A = Kategorie der MATERIAL-Liste (Engine, Bridge, Qualifikation, Gates, Pilot-Entscheidungslogik, Rules-/Evidence-/Privacy-Text, Policy-Text, Containment/Security, Workflows): Frischkontext-Review **plus** Kreuz-Review der anderen Agentenfamilie (Claude ↔ Gemini, beide Richtungen; Anforderung als Kommentar in #1167). Klasse B = nur Größe >300 Zeilen: Frischkontext-Review genügt. Jeder Review-Kommentar nennt die Klasse.
- **Umgebungsfallen:** installiertes `commander_lab` zeigt oft auf einen älteren Checkout: bei **jedem** pytest-Lauf `PYTHONPATH=<clone>/src` und `python -c "import commander_lab; print(commander_lab.__file__)"` im Bericht; flache Klone lassen `test_bridge_qualification_states` und 3× `test_benchmark_xmage_full_games` rot (Referenz-Commit fehlt): nur „auch auf main rot“ gelten lassen, wenn mit gesetztem PYTHONPATH auf main nachgelaufen; mit `COMMANDER_LAB_CACHE_CHECK=1` ist `test_a_window_that_writes_an_undeclared_group_drops_everything` absichtlich rot; `ci-definition-integrity-shadow` ist eine Hilfsprüfung (kein Gate). `gh api` und Backticks im Shell-String: Kommentartext immer aus einer Datei (`-F body=@datei`), nie per `-f body="…`…`…"`. **Nie `POST /issues/N` für Kommentare** (überschreibt die Beschreibung); Kommentare gehen an `/issues/N/comments`. Label mit Doppelpunkt: `labels=needs%3Aowner` kodieren.
- **Quota:** höchstens 2 große Agenten gleichzeitig; Opus nur für Hidden-Info, Statistik, Kill-/Gate-Logik; sonst Sonnet; Delta-Reviews von wenigen Zeilen selbst lesen. Bei Limit: Agent per SendMessage fortsetzen (Arbeit bleibt gespeichert).
