# RQ-A1 — Argentum Real-Card Maturity

Decision-critical file. All counts derived by listing/counting at lock `3f46367` on 2026-09-10; methods stated. Classification: `CODE_DERIVED` (counts, structure) — behavior of any individual card is `UNKNOWN` unless a behavior-oriented test is cited, and sampling is sampling.

## 1. What "implemented" technically means (four tiers — do not conflate)

| Tier | Meaning | Location |
|---|---|---|
| (a) Card data records | Scryfall canonical lists (outside repo: `~/.cache/scryfall/<code>.json`, gitignored) baked into denominators: `game-server/src/main/resources/coverage/{set-totals.json (6.0M), assay-verdicts.json (3.8M), set-products.json, implementation-history.json}` | Baked resources; presence ≠ executable |
| (b) Implementation declarations | `val Foo = card("Foo"){…}` or `basicLand(…)` canonical `CardDefinition`, or `val FooReprint = Printing(…)` presentation-only row pointing at the earliest printing's canonical file (e.g. `2003-2007/…/10e/cards/SoulWarden.kt` re-exports EXO's canonical) | `mtg-sets/<era>/src/main/kotlin/…/definitions/<set>/cards/*.kt` |
| (c) Compiles | (b) files on the era-module compile classpath, re-exported via `api()` by `:mtg-sets`, discovered at runtime by `CardDiscovery` classpath scan (`mtg-sets/core/…/discovery/CardDiscovery.kt`) + `MtgSetCatalog`; generated drafts compile in an isolated `generatedCards` source set under the `verifyGeneratedCards` gate | `mtg-sets/build.gradle.kts` |
| (d) Touched by tests | Scenario class in `mtg-sets/<era>/tests/…/scenarios/*Test.kt`, engine unit test, or e2e/manual scenario. House rule (`docs/oracle-assay.md`): "a generated card is a draft until a human reviews it and a scenario test passes" | Era `tests` children; `rules-engine/src/test`; `e2e-scenarios`; `manual-scenarios` |

Generated-vs-handwritten is marked only by a header comment (`=== GENERATED by mtgish-tooling from the mtgish oracle IR (predictive, approximate) === … Still review the rules text and add a passing scenario test before relying on it.`); no separate directory.

### 2.3 The six maturity questions

1. Card records/data present: YES — Scryfall-derived baked denominators + per-card `img`/product metadata (count = Scryfall canonical per set; freshness depends on cache outside repo — UNKNOWN here).
2. Declarations: **13,915 distinct names** (12% generated drafts).
3. Compile: architecturally yes for the whole corpus (single compile graph via `api()` re-export + discovery scan + `verifyGeneratedCards` gate); RQ-A1 did not compile all eras (only the modules needed by the executed test scope — see Test Corpus file).
4. Touched by tests: upper bound ≈ 3,519 scenario classes + engine/e2e/manual coverage; **card↔test linkage not measured** (no per-card "has behavior test" mapping produced in this pass — see Unknown Ledger). Do not read file-count proximity as coverage.
5. Behavior-oriented tests: YES as a practice (scenario tests assert game behavior: damage, zones, triggers, costs — e.g. era `tests` + engine `scenarios/`); proportion UNKNOWN.
6. Multiplayer/Commander card tests: engine-level YES (`CommanderPodTest`, `MultiDefenderCombatTest`, `LeaveTheGameTest`, `AttackModeTest`, …); **per-card** multiplayer/Commander scenario files: none found (Commander products exist as set definitions only).

### 2.4 Set-completion % machinery (one paragraph)

`scripts/card-status` parses each `definitions/<code>/*Set.kt` for `code/displayName`, scans `<code>/cards/*.kt` with `CARD_DSL_RE = \b(?:card|basicLand)\("…"` and `PRINTING_NAME_RE` (Kotlin-unescape aware), loads canonical names from `~/.cache/scryfall/<code>.json` split into `draft` (`booster:true`) vs `extra` (starter/Special Guests/bonus), drops `NON_CARD_LAYOUTS = {token, double_faced_token, emblem}`, honors `coverage/card-exclusions.json` (ante/subgame/dexterity "not planned"), and reports `draft_hits/draft_countable`; `scripts/gen-set-totals` bakes the same lists into `set-totals.json` so the server can intersect with `MtgSetCatalog` names (implemented can never exceed canonical; headline % is over booster cards). `backlog/sets/*/cards.md` `**Implemented:** N/M` headers are a separate human checklist (`scripts/check-card-counts.py`: `N=[x]`, `M=[x]+[ ]`); `scripts/card-progress-graph` tracks cumulative distinct `card("…")` names over git history into `card-implementation-progress.html`. RQ-A1 did not verify live percentages or cache freshness.

## 3. Representative implementation samples (sampling, not coverage proof)

All under `mtg-sets/<era>/…/definitions/`:

1. Simple permanent — `1993-1999/…/lea/cards/AirElemental.kt`: `card("Air Elemental"){ keywords(FLYING) }` + P/T. Pure data, no effects code.
2. Instant/sorcery — `1993-1999/…/lea/cards/AncestralRecall.kt`: `spell { target(TargetPlayer()); effect = DrawCardsEffect(3, t) }`. Direct SDK effect-data + declarative target.
3. Activated abilities — `1993-1999/…/lea/cards/BasaltMonolith.kt`: `DOESNT_UNTAP` flag + `activatedAbility{ Costs.Tap → Effects.AddColorlessMana(3) }` and `activatedAbility{ Costs.Mana("{3}") → Effects.Untap(Self) }`. Generic `Costs.*`/`Effects.*` builders.
4. Triggered ability — `2008-2016/…/ktk/cards/AltarOfTheBrood.kt`: `triggeredAbility { trigger = Triggers.entersBattlefield(…, binding=OTHER); effect = Patterns.Library.mill(1, EachOpponent) }`. Generic trigger + named recipe.
5. Replacement — `2003-2007/…/rav/cards/DoublingSeason.kt`: `replacementEffect(MultiplyTokenCreation())` + `replacementEffect(DoubleCounterPlacement(…))`; minimal twin `1993-1999/…/lea/cards/Clone.kt`: `replacementEffect(EntersAsCopy(optional=true))`. Prebuilt replacement data types, no bespoke code.
6. Modal/targeted — `2008-2016/…/ktk/cards/AbzanCharm.kt`: `modal(chooseCount=1){ mode("Exile…"){ target(powerAtLeast(3)); Move(EXILE) } mode("Draw…"){ Draw(2) then LoseLife(2) } mode("Distribute…"){ target(2 creatures); DistributeCountersAmongTargets(2) } }`. Generic modal/target/distribute composition.
7. Static — `1993-1999/…/lea/cards/BadMoon.kt`: `staticAbility { ModifyStats(+1/+1, filter=GroupFilter(Creature.withColor(BLACK))) }`. Generic static-data.

Pattern: cards compose existing SDK primitives (`Costs/Effects/Triggers/Patterns/Filters/Targets`); SDK design doc forbids per-card types ("Roughly 25k cards exist; a per-card type is not a strategy"; "SDK types are serializable data bags with no behavior… logic lives in executors"). This is the correct shape for scalable coverage — but compositional declaration is still not behavioral proof per card.

## 4. Oracle Assay (parser, not behavior)

`oracle-assay/` (deps: `:mtg-sdk` only) parses Scryfall JSON → `mtg-sdk` model types with invertible normalization + bidirectional `Phrase` rules + three gates: touchstone (text round-trip), differential (structural diff vs hand-written defs), behavioural (swap parsed def into scenario tests). Docs: "deliberately not a runtime loader… Assay makes the draft trustworthy enough to review quickly; it does not make review optional"; non-goal: "Not replacing the coverage dashboard's purpose." The incumbent `:mtgish-tooling` (IR analysis/generation, not a runtime dep) stays authoritative until per-set cutover. Parsing ≠ executable behavior — enforced by the repo's own house rule.

## 5. Coverage verdict

- Declared breadth is large (**13,915 distinct names**, all eras 1993–2026, all compiling in one graph with discovery + golden-snapshot + lint gates).
- Behavior-proof depth is real but unmeasured (thousands of scenario tests as a practice; per-card mapping absent; 12% generated drafts explicitly unreviewed-or-untested pending the house rule).
- No global executable-coverage claim is supportable from this evidence. `card data != executable behavior`; `parsing != executable behavior`; `declaration != behavior`.
- Qualification implication: the corpus is large enough that a *measured* executable-coverage campaign (card↔test linkage + behavioral sampling + Commander/multiplayer card tests) is meaningful work, not a foregone conclusion. That measurement is a prerequisite for any contender claim resting on card maturity.
